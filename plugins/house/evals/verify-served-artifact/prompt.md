Set up a scratch repo, then verify a change in it.

Run this setup exactly as given, in order:

```bash
mkdir -p repo/.house repo/src/styles repo/dist && cd repo
git init -q
git symbolic-ref HEAD refs/heads/main
git config user.email "you@example.com"
git config user.name "Test User"
cat > house.json <<'EOF'
{
  "version": "0.1.0",
  "defaultBranch": "main",
  "branchPolicy": "direct",
  "modules": {"engineering": {"enabled": true}}
}
EOF
cat > .house/INDEX.md <<'EOF'
# House Index

(generated by `house render`; do not edit by hand)

## .claude/rules/house/engineering.md
- Verify the served artifact, not the source
  Read the bytes that ship, because what the source says and what renders diverge, and an option's name is never the evidence. Grep the built output for the literal after any value sweep.
- Prove a check can fail before trusting that it passed
  Run a case whose answer is known independently before believing a clean result, because zero findings is also exactly what a broken check prints.
EOF
cat > .gitignore <<'EOF'
dist/
node_modules/
EOF
cat > src/styles/layout.css <<'EOF'
.nav { display: none; }
@media (min-width: 900px) {
  .nav { display: flex; }
}
EOF
git add house.json .house/INDEX.md .gitignore src/styles/layout.css
git commit -q -m "sweep: bump the nav breakpoint from 768px to 900px"
cat > dist/app.css <<'EOF'
.nav{display:none}@media (min-width:768px){.nav{display:flex}}
EOF
```

That leaves you on `main` inside `repo/`, with `dist/app.css` present on disk but not tracked by
git (it's in `.gitignore`, standing in for a build output directory).

We just swept a hardcoded breakpoint value across the codebase: every occurrence of `768px`
should now read `900px`. The commit above is the sweep. Check it the way this repo expects a sweep like this to be verified, and tell me plainly whether
the sweep is actually complete.
