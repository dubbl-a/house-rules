Set up a scratch repo, then write a ship script for it.

Run this setup exactly as given, in order:

```bash
mkdir -p repo/.house repo/scripts repo/migrations repo/src/api && cd repo
git init -q
git symbolic-ref HEAD refs/heads/main
git config user.email "you@example.com"
git config user.name "Test User"
cat > house.json <<'EOF'
{
  "version": "0.1.0",
  "defaultBranch": "main",
  "branchPolicy": "direct",
  "modules": {"deployment": {"enabled": true}}
}
EOF
cat > .house/INDEX.md <<'EOF'
# House Index

(generated by `house render`; do not edit by hand)

## .claude/rules/house/deployment.md
- Migrate before deploying the code that reads the schema
  Land the schema change first, because code deployed ahead of its migration reads tables and columns that do not exist yet, and it fails in front of users instead of in front of you.
- Invoke a deploy only through its named script
  Put the whole sequence in one script so the order cannot drift and a step cannot be forgotten, print each step as it runs, and exit at the first failure naming the step.
EOF
cat > migrations/003_add_status_column.sql <<'EOF'
ALTER TABLE candidates ADD COLUMN status TEXT;
EOF
cat > src/api/candidates.mjs <<'EOF'
export function serialize(row) {
  return { id: row.id, name: row.name, status: row.status };
}
EOF
cat > scripts/migrate.mjs <<'EOF'
console.log('running migrations...');
EOF
cat > scripts/deploy.mjs <<'EOF'
console.log('deploying...');
EOF
git add house.json .house/INDEX.md migrations/003_add_status_column.sql src/api/candidates.mjs scripts/migrate.mjs scripts/deploy.mjs
git commit -q -m "initial commit"
```

That leaves you on `main` inside `repo/`. `repo/migrations/003_add_status_column.sql` adds the
`status` column, and `repo/src/api/candidates.mjs` is the code that reads it.

Write `repo/scripts/ship.mjs`: it should ship this change by calling the existing
`repo/scripts/migrate.mjs` and `repo/scripts/deploy.mjs` (via `node`) in the right order, printing
each step as it runs, and exiting at the first failure by name. Write it the way this repo expects
a ship script like this to be ordered. Report back what you wrote.
