# Rule-load re-count, 2026-10-17

Item 5 of #160: rerun the load count once the InstructionsLoaded log covers a longer period, and find out why four adopters log nothing. A point-in-time record. Read each figure as of this date.

## Source and method

The plugin's InstructionsLoaded hook (`plugins/house/hooks/instructions-loaded.mjs`) appends one line per instruction-file load to a per-key log on the maintainer's machine. The log covers 2026-09-09 to 2026-10-17, about five and a half weeks.

Each repo's logs were pooled across:
- its main checkout;
- its linked worktrees, which log under `<root>-.claude-worktrees-<name>`;
- sessions started in a subdirectory;
- its old path under `~/Documents` and its new path under `~/code` (the repos moved around 2026-10-05).

A rule counts as loaded in a session if any event in that session names it, whatever the `load_reason`. Session counts include short worktree and subagent sessions, so the shares below understate how often a rule loads in a full working session.

Adopter repos are aliased. The package repo itself is `package`.

## Why four adopters seemed to log nothing

The hook keyed each log by the session's `cwd`, and `house doctor` reads only the log keyed by the main checkout's root. So doctor missed:
- every worktree session (for `package`, 87 of its 89 log files are worktree keys);
- every session started in a subdirectory;
- every log written under a repo's old path before it moved.

An adopter worked mostly in worktrees looked like it logged nothing. The fix keys every log by the main checkout's root, and has doctor read the old worktree-keyed logs too (#160's follow-up PR).

One adopter (`F`) truly has no log. Its commits in the period come from the cloud routine and from adopter syncs, so no local Claude Code session ran there. That is expected, not a fault.

## Findings

1. **A rule that loads at session start is not scoped.** D's vendored `engineering.md` lists `- *.mjs` unquoted in its `paths:` frontmatter. In YAML a bare value starting with `*` is an alias, so the frontmatter fails to parse, and Claude Code loads the rule as if it had no `paths:`. The checker did not flag it. Filed as #271. The fix makes render quote every glob, and makes the checker report a frontmatter value YAML would reject.
2. **Rules that never loaded:**
   - `evals.md` in A and `package`;
   - `retrieval.md`, `security-server.md`, `database.md` and `data-pipelines.md` in A;
   - `security-server.md` in B;
   - `github.md` and `llm-output.md` in C;
   - several in D.

   This means no session touched a file matching their paths in the period. It is not evidence that a rule is useless, and it is not a trim signal by itself: a scoped rule is meant to stay out of sessions that never touch its domain.
3. **The shares are lower bounds.** Short subagent and worktree sessions inflate the denominators.

## What this settles for #160

The re-count is done, and the "log nothing" finding is explained and fixed. Neither result calls for cutting a rule. A future trim pass should weigh a never-loaded rule against whether its domain exists in that repo at all, not against the load count alone.
