# Token cost levers and adopter usage (2026-10-20)

Research note. No rule, hook, agent, setting or plugin file changes with this note; the proposal section is for later PRs.

## Short answer

For interactive Claude Code sessions on a seat plan, most spend is the conversation being resent every turn, not the model's own output. In the one adopter transcript set analyzed below, cache reads and cache writes were about 89% of list-price cost and output was about 11%. The levers with primary-source support, in order:

1. Protect the prompt cache: avoid model switches mid-session, avoid resuming after the TTL has lapsed, keep the prefix stable.
2. Keep sessions short and contexts small: `/clear` between unrelated tasks, hand off instead of resuming a huge idle session.
3. Pin cheaper models and lower effort on subagents, and escalate to Opus on evidence.
4. Use effort, not thinking budgets or output caps, to trade quality for cost.
5. Keep the always-on footprint small (descriptions, CLAUDE.md, MCP).
6. Measure first: every dollar figure client-side is a list-price estimate.

See the evening addendum for what native Claude Code already covers (idle compaction, the resume warning).

Caveat that applies throughout: billing depends on the plan. On seat plans with an allowance, usage inside it is not metered in dollars, so "savings" mostly means headroom under usage limits. On usage-based Enterprise, the seat includes no usage and every token bills at API rates (https://support.claude.com/en/articles/11526368), so savings are dollars. Several docs diagnoses (Opus as default driving spend) are scoped by Anthropic to API and cloud plans.

## How this was researched

One deep-research run: 6 angles, 365 agent calls, 27 sources fetched, 110 claims extracted, each verified by three votes. 104 were confirmed and 6 refuted, leaving 22 findings after synthesis. Most primary claims come from Claude Code docs fetched on 2026-10-20, current to v2.1.305 and the 5.5 models. Source quality: primary (Anthropic docs and engineering posts), secondary and blog sources used only to aim measurement.

Refuted claims, which this note does not rely on:

- Opus 4 lead with Sonnet 4 subagents beating single-agent Opus 4 by 90.2% as support for cheaper subagent models (0-3).
- Thinking defaults to 31,999 tokens and `MAX_THINKING_TOKENS=10000` saves about 70% (0-3).
- The Team and Enterprise dashboard shows only adoption metrics and no token metrics (1-2).
- A wide claim that hook input carries no token or cost counts except on SessionStart resume or fork, so runaway detection must read the transcript or model-switch events (0-3). The SessionStart fields themselves are confirmed: the session re-read the hooks reference, which documents `seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired` and `estimated_cache_write_usd` on resume or fork (v2.1.251+, once the transcript has a response).
- Cache creation costs about 3.5x cache reads, and strict TDD cost $7.50 against $14.00 default (0-3).
- A four-level effort scale with `max` accepted only through the environment variable (0-3).

## Where tokens go

### Documented

- Baseline: Anthropic reports enterprise deployments average about $13 per developer per active day and $150-250 per developer per month, with 90% of users under $30 per active day. List-price estimates, no method given. https://code.claude.com/docs/en/costs (high confidence)
- The full conversation is resent each request and re-read at the cached rate: about a tenth of base input, about a twentieth on Opus 5.5 and Sonnet 5.5. Writes cost 1.25x (5-minute) or 2x (1-hour). A 200k context is about $0.60 per turn uncached against $0.06 cached. https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence (medium confidence overall; the pricing arithmetic is documented)
- Vendor figure, weak source: one 20,000-session analysis put spend at about 63% re-reads, 25% cache writes, 11% output. https://coralogix.com/blog/where-did-all-my-claude-code-tokens-go Use it only to aim measurement.
- Cache breakers: model switches (each model has its own cache), opusplan plan-mode toggles, skills that name a different model, per-request text placed before the stable prefix. Plugin skills, agents, commands and hooks, and MCP servers connecting mid-session with deferred tools, do not invalidate the cache. https://code.claude.com/docs/en/prompt-caching (high)
- TTL buckets: on a subscription within plan usage the main conversation gets 1 hour; subagents, workflows, teammates and compaction get 5 minutes; API-key and cloud-provider auth get 5 minutes everywhere. `promptCacheTtl` and `subagentPromptCacheTtl` (v2.1.242+) override each bucket. A 1-hour write pays off only when roughly 1 turn in 20-30 follows a pause of 5 to 60 minutes. (high)
- Fan-out: single agents about 4x a chat, multi-agent systems about 15x (research workloads, not coding), agent teams about 7x (vendor approximation). https://www.anthropic.com/engineering/multi-agent-research-system (high)
- A real incident: the April 2026 postmortem found a thinking-clearing bug that caused cache misses and drained usage limits, fixed in v2.1.101. https://www.anthropic.com/engineering/april-23-postmortem

### The adopter's evidence

Source: transcripts of one adopter's GTM repo, 2026-07-21 to 2026-10-20: 55 sessions, 20,644 deduplicated responses. The aggregates were independently re-verified. All dollar figures are list-price estimates.

| Cut | Result |
|---|---|
| Total | $1,805 |
| By model | Opus 5.5 $1,187; Fable 5.1 $412; Sonnet 5.5 $171 |
| By thread | Main sessions $1,288; subagents $517 |
| By token type | Cache reads $817; cache writes $786; output $202; uncached input about $0 |
| Cache hit rate | 96.8% |

Context size is the driver:

- Main turns over 200k context were 74% of turns and 84.5% of main cost. Over 500k: 31% of turns and 48% of main cost. Peak context 962k. No compactions occurred.
- The top 15 sessions hold 82% of tokens.

Cache writes are the surprise. They are about 44% of cost here, against 25% in the vendor split above (a weak source, so the gap is a prompt to measure, not a finding):

- Main-thread writes $465, all 1-hour TTL. Of that, $247 came from 63 rebuilds after an idle gap over 1 hour: the cache expired and the whole context was written again.
- Subagent writes $321, all 5-minute.

Subagent cost by type: workflow agents $212 ($121 on Opus); builder $143 ($102 on Opus, even though the builder definition pins Sonnet, because the orchestration rule lets hard builds go to Opus); refuter $83 (Opus by design); general-purpose $58; researcher $14.

Other: effective effort was medium. Tool output (text only) was 51.4M characters: Bash 28.8M, Read 11.8M, MCP 3.9%. Images were counted but not priced.

Caveat: transcript per-step `output_tokens` can be placeholders, so output cost may be undercounted. The SDK docs say the same: per-step output is a placeholder, and the result message carries the real figure. https://code.claude.com/docs/en/agent-sdk/cost-tracking

Reading: idle rebuilds and very large contexts, not a lack of caching, are where this adopter's money went. That points at session hygiene (R1) and resume guards (G1) before model tuning.

### Pricing multipliers worth a doctor check

Documented at https://platform.claude.com/docs/en/about-claude/pricing: fast mode costs 2x on Opus 5.5; US-only inference costs 1.1x; legacy Opus 5 and Opus 4.8 cost 25% more per token than Opus 5.5.

## Levers by area

Each lever lists evidence grade (documented, measured by Anthropic, vendor, or opinion) and the quality cost.

### Cache

- Do not switch models mid-session; start a new session on a tier change. Documented (prompt-caching). Quality cost: none, but the task may need the other model.
- Warn before resuming a session whose cache has likely expired. SessionStart on resume or fork carries `context_tokens`, `estimated_cache_write_usd` and `prompt_cache_likely_expired` per the hooks reference (https://code.claude.com/docs/en/hooks, v2.1.251+). Quality cost: none.
- 1-hour TTL where the default is 5 minutes (API-key and cloud billing). Documented break-even about 1 in 20-30 turns after a pause. Note the cost guide says a warm 5-minute cache can cost less on the 5.5 models and Fable. Open question for subagents on seat plans.

### Model

- Defaults: Pro, Max, Team and Enterprise default to Opus 5.5. Docs recommend Sonnet for most coding, Opus for hard reasoning and architecture, Haiku for simple subagents. https://code.claude.com/docs/en/model-config
- Subagents and built-in Explore and Plan inherit the session model unless frontmatter sets `model` and `effort`. Resolution: per-invocation, frontmatter, `CLAUDE_CODE_SUBAGENT_MODEL`, main model. `model: inherit` does not carry effort. https://code.claude.com/docs/en/subagents (high)
- Quality cost: the docs give no measured cost of defaulting to Sonnet or Haiku. Opinion only: a community claim that Sonnet handles 80%+ of work at 60% less than Opus; unsourced, and current prices do not support the 60% figure.

### Effort

- 5.5 models default to medium; thinking cannot be disabled; `MAX_THINKING_TOKENS` only affects fixed-budget models. Effort is the lever. (high)
- Anthropic data, Opus 5.5 on SWE-bench Pro: low effort 87.4% at $0.11 per task; high 95.3% at $0.29; low with failures re-run at high about 97% at about $0.17. Needs a failure signal such as tests; adds wall-clock on failures; subset, two runs pooled.
- Quality evidence: lowering the default from high to medium in March 2026 was judged the wrong trade-off and reverted in April (postmortem). Current 5.5 default is medium.

### Context and output

- `/clear` is free. `/compact` is cheap while the cache is warm and expensive after an idle gap past the TTL; compact at natural breaks. On 5.5 models rewriting earlier tool results invalidates later thinking blocks, so compaction is preferred over context editing. (high)
- Measured by Anthropic on an earlier model: pruning stale tool results saved 39% on a long task and nothing on short ones; context editing made a short run cost 73% more.
- Hooks can trim tool output: PreToolUse `updatedInput` rewrites a Bash command (the costs page sample pipes test runs through grep and head); PostToolUse `updatedToolOutput` replaces a result. Docs say "tens of thousands of tokens to hundreds", illustrative only. Quality cost (verifier inference): the filter can drop passing summaries, context and the real exit code.
- Cutting the wrong tokens hurts, measured: `max_tokens` 16,384 solved 57.6% against 75.6% at 64,000; a 25-word cap between tool calls cost about 3% on coding evals and was reverted. Do not write a rule that caps working text.
- Truncation: hook-injected text is capped at 10,000 characters (documented). Other tool-result limits (about 50K to file, 2KB preview, 200K per message, Bash about 30K) are blog figures; check the installed version.
- Autocompact thresholds are low-confidence and inconsistent across versions; do not ship advice built on a specific percentage.

### Fan-out

- Anthropic's scaling rules: 1 agent with 3-10 tool calls for simple lookups, 2-4 subagents for comparisons, more than 10 for complex research. Multi-agent setups pay off when task value is high; most coding has few parallelizable parts. `maxTurns` caps subagent turns. The plugin-side equivalent is a brief that sizes how much an agent should read.
- Adopter evidence: subagents were 29% of cost; about a quarter of that was Opus workflow agents.

### Plugin footprint

- Names, descriptions and `when_to_use` of skills, agents and commands load every session where the plugin is on. `claude plugin details <name>` estimates always-on and on-invoke cost. Hooks cost no model context. https://code.claude.com/docs/en/plugins/measure (high)
- CLAUDE.md: aim under 200 lines, move workflow into skills. Explore and Plan skip CLAUDE.md; custom subagents load it unless `omitClaudeMd` (v2.1.271+). No savings figure documented.
- MCP: tools are deferred by default; Anthropic measured tool search at $0.56 against $1.02 with 502 tools loaded (earlier model). Tool search is off with a custom `ANTHROPIC_BASE_URL`, `ENABLE_TOOL_SEARCH=false`, or older models on one cloud. CLI tools beat MCP servers. Quality cost: shorter descriptions can stop skills triggering; re-run evals.

### Enforcement limits

- Exit code 2 blocks PreToolUse, UserPromptSubmit, Stop and PreCompact; on PostToolUse it only warns after the fact. Hook timeouts fail open unless `onFailure: block` (v2.1.295+). Hook entries merge across settings levels. `allowManagedHooksOnly` blocks plugin hooks unless the plugin is force-enabled in managed `enabledPlugins`. PreModelSwitch blocks user or client switches only, not automatic restores. (high)
- `--max-budget-usd` works only in headless runs. `modelPricing`, `availableModels`, `deniedModels` and `availableModelsMatch` are honored only from managed settings. OpenTelemetry exporter variables in a repo's `.claude/settings.json` are ignored. A plugin cannot cap interactive spend; binding limits come from managed settings or a gateway.

### Measurement

- `/usage` shows a "Prompt cache (main)" line (v2.1.251+) plus attribution to skills, subagents, plugins and MCP servers. The status line exposes a `prompt_cache` object (hit ratio, misses, ttl, expiry) at zero token cost; it covers the main conversation only. https://code.claude.com/docs/en/statusline
- OpenTelemetry: `claude_code.token.usage` by type and model, `query_source` on API request events, `tool_result_size_bytes` on tool results. No dedicated hit-rate metric; derive cacheRead / (input + cacheRead + cacheCreation). Admins enable it through managed settings. https://code.claude.com/docs/en/monitoring-usage
- Org level: spend report export, or the Enterprise-only Analytics API (not on Teams). https://code.claude.com/docs/en/analytics
- Transcript analysis must deduplicate by message ID and treat per-step output as a placeholder.

## Proposal for house-rules

Rule advice (rule or skill text, no code):

- R1, session hygiene: one task per session; `/clear` between unrelated tasks; a handoff note plus a fresh session when stepping away from a large one; `/compact` only at natural breaks while the cache is warm.
- R2, choose the model when the session starts; a tier change means a new session; avoid opusplan toggles on large contexts; skills that set a model use `context: fork`.
- R3, escalate the builder to Opus only after a Sonnet build fails review.
- R4, medium effort by default; low effort with a re-run at high where tests give a failure signal. Effort, not thinking budgets, is the lever.
- R5, fan-out sizing rules in briefs, following Anthropic's 1 agent / 2-4 / 10+ scale.
- R6, trim tool output as it arrives; never rewrite earlier results.

Guards (each reads its own opt-out or threshold so users and sessions can override):

- G1, a SessionStart resume warning using `prompt_cache_likely_expired`, `context_tokens` and `estimated_cache_write_usd`.
- G2, a PreModelSwitch warning that a switch re-reads the whole context uncached. Its input carries `from_model` and `to_model` but no context size, so a size threshold would need the transcript (which lags) or the hook's own state; start with an unconditional warning.
- G3, an opt-in Bash test and log output filter. State the risks: lost exit code, dropped passing summaries, lost context.
- G4, an idle-gap warning on prompt submit. No common hook input carries timing or cost (the common fields are session, prompt, transcript path, cwd, permission mode, effort, event name), so the hook would have to keep its own last-response timestamp, for example from a Stop hook. Build only after a prototype shows it is reliable.

Settings defaults:

- S1, `omitClaudeMd` on scout and researcher.
- S2, `promptCacheTtl` 1h guidance where billing is API or usage credits (default TTL 5 minutes there); the doctor checks first.
- S3, a status line built on `prompt_cache` and context size.

Measurement:

- M1, a transcript-analysis skill or doctor mode (by model, agent type, context band, idle rebuilds) that carries the placeholder-output caveat.
- M2, doctor checks for version floors (v2.1.242, .251, .257, .271, .283, .295 for the features above), CLAUDE.md length, the plugin's always-on cost (`claude plugin details`), fast mode, US-only inference, legacy model pins and `allowManagedHooksOnly`.
- M3, OpenTelemetry setup guidance (managed or user level only).

Admin-only levers to document, which the plugin cannot set: managed `availableModels` and `deniedModels`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, `modelPricing`, the Analytics API and the spend report.

Suggested order, given the adopter evidence: R1 and G1 (idle rebuilds and huge contexts), then M1 (so effects can be checked), then R3 and S1 (subagent Opus share), then the rest.

## Addendum: later the same day

Measured by the session with the scripts in `scripts/`, on the same adopter data unless stated otherwise. All figures are list-price estimates.

- **Idle rebuilds happen in live sessions, not on resume.** Of the 65 rebuilds over 50k tokens after a gap of more than an hour (about $257), the transcripts hold 52 startup markers and no resume markers. At least 60 rebuilds (about $229) came from a session left open and returned to. G1 fires only on resume or fork, so it would have caught almost none of this. **G4 is the guard that matches the pattern**, and it moves ahead of M1. A prompt-submit hook can read the transcript's last response (timestamp and token count; after an hour of idle the asynchronous write has landed) and the cache lifetime (1 hour on a subscription, 5 minutes on API billing). Risk: the transcript format is internal.
- **Startup load.** First-request context: main sessions median 71k (10th to 90th percentile 63k to 79k, n=55); subagents median 58k (19k to 61k, n=1,360). About 19k is the harness's own system prompt and tools.
  - `/context` at a session start: 38.8k in the package repo and 45.2k in the adopter repo, where the memory index was 6.4k of it. It apparently does not count the deferred tool-name list.
  - Headless test, one run per setting, no project CLAUDE.md:

    | Setting | Startup input |
    |---|---|
    | Default | 46.0k |
    | `disableClaudeAiConnectors: true` | 34.6k |
    | `deniedMcpServers` (5 connectors) | 40.5k |

    So blocking a connector removes its deferred names and server instructions, not just its tools. `--model haiku` was overridden to Sonnet in those runs, cause unknown.
  - 9 connectors and plugin servers loaded in the adopter repo were never called in three months.
  - Estimated cuttable load: 13k to 15k per main request, worth about 4% of cost. That is modest next to session hygiene.
- **Per-project switches** (documented, cited in the session's research): `/mcp` toggles a connector per project (stored in `~/.claude.json`). `enabledPlugins` works in `.claude/settings.local.json`. `skillOverrides` covers user, project and built-in skills, not plugin skills. Synced claude.ai skills are turned off on claude.ai, or all of them with user-level `syncClaudeAiSkills: false`. `deniedMcpServers` printed "blocked by enterprise policy" in the test; whether it works from a project file is unverified.
- **Builder model.** Opus builds ran a median 111 responses against 43 for Sonnet, but Opus got the harder builds, so that comparison is selection bias, not evidence. Linking refuter verdicts to the builder's model failed: only 1 of about 101 refuter runs exposed a parseable ACCEPT or REWORK. M1 needs the refuter to end with one machine-readable verdict line. Proposed R3 nuance: start on Opus when a miss is expensive to detect or redo (invariants across modules, no automated signal, a prior Sonnet attempt that failed on reasoning). Start on Sonnet when the brief names files and a checkable success condition. Try Sonnet at high effort before Opus. If the brief cannot state the design, plan first. Rough break-even: Sonnet-first stops paying once it fails review about 30 to 40 points more often than Opus on a task class. That is arithmetic, not a measurement.
- **Session length is staleness, not size.** There is no price step at 200k: the 1M window bills at the standard rate, so cost is linear, about $0.04 per Opus turn at 200k of cache reads and $0.10 at 500k. Clear when most of the context is finished work, not at a token count. Unverified: no checked claim measured quality loss against context length.
- **Effort, corrected.** Effort changes how much work a task takes, not just its output (Anthropic's SWE-bench Pro ladder, above), so it is a real lever with a measured quality cost, not a minor one.

## Addendum: idle compaction and native overlaps (2026-10-20, evening)

This note did not mention Claude Code's idle compaction. Since 2.1.299 a conversation of 200K+ tokens left idle for about 54 minutes is compacted before its one-hour prompt cache expires. It is on by default (`"idleCompaction": false` turns it off; `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` sets the size). Scripts: `idle_versions.py`, `idle_sleep.py`, `compactions.py`. Same adopter data; every dollar figure is a list-price estimate.

Live-session idle rebuilds (cache write over 50k, gap over 1h, same test as `resumes.py`), as of the evening of 2026-10-20; a later run counts later sessions too:

| Claude Code | Context | Rebuilds | Cost | Dates |
|---|---|---|---|---|
| before 2.1.299 | under 200k | 9 | $10 | 07-21 to 10-06 |
| before 2.1.299 | 200k or more | 35 | $168 | 07-29 to 10-14 |
| 2.1.299 or later | under 200k | 5 | $4 | 10-19 to 10-20 |
| 2.1.299 or later | 200k or more | 12 | $48 | 10-15 to 10-20 |

All 12 in the last row ran the CLI on 2.1.300 to 2.1.304 with a 1h TTL, contexts of 206k to 800k and gaps of 73 to 924 minutes. `idleCompaction` was unset in user and project settings, so the default applied. The evidence that no compaction ran is the context size: in all 12 the first request after the gap carried the same or more context than the last one before it, and no gap over 50 minutes on 2.1.299 or later shows a large context dropping to a small one. The transcripts also hold no compaction record of any kind, but they have none in three months, so `compactions.py` has never seen a real one to compare against. Rerunning `resumes.py` now gives 61 live-session rebuilds ($230), against "about 60, $229" above, because more sessions have been added.

Sleep split, from `pmset -g log` (kept from 2026-10-13) at the +54 minute mark of each gap: 5 awake for the whole first 54 minutes, 1 more awake at the moment compaction should fire (44 of 54 minutes awake), 6 asleep or in DarkWake. Idle compaction did not prevent any of the 12 rebuilds, and sleep explains about half of them. That assumes the idle timer counts wall-clock time; if it pauses while the Mac sleeps, one more gap (10-14, 98 minutes awake) reached its fire point awake, and sleep explains 5 of 12.

Hypotheses, unverified: a pending permission or question dialog blocks idle compaction; some unnamed condition does. Reproduction test: a terminal session over 200k, `caffeinate -i`, left idle for one hour, then check whether a compaction record appears.

Overlaps with the proposal:

- 2.1.304 added a warning on Pro and Max when resuming an inactive conversation would use a noticeable share of the 5-hour limit. That overlaps G1 (`plugins/house/hooks/resume-cost.mjs`). Whether G1 still adds value on API billing or other plans is unchecked.
- `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` (issue #324) is ruled out as a cause on the adopter machine: it is unset. Only `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` is set (user settings), and agent frontmatter overrides it since 2.1.251.
- Other native features that touch the proposal: `omitClaudeMd` (2.1.271), the `prompt_cache` statusline object (2.1.251), the miss cause shown by `/cost` (2.1.260), OTel `cache_creation_5m_tokens` and `cache_creation_1h_tokens` (2.1.300), `/usage` fixes (2.1.305).
- Prior art found for the proposal, checked the same day and recorded on issues #321 to #325: the official `session-report` plugin (anthropics/claude-plugins-official, Apache-2.0) reports tokens, cache breaks, subagents by type and skills from the same transcripts, but has no cost, model, MCP or rebuild-cause split; `/usage` attributes usage to skills, subagents, plugins and MCP servers; the built-in Explore and Plan agents already start without CLAUDE.md, the precedent for S1. A status line cache display suits only someone watching it, so G4 stays a hook. M1 narrows to the gaps those tools leave.

## Addendum: builder tier evidence (2026-10-20, late)

Settles the two open points behind R3 (issues #324 and #344). All figures are list-price estimates from the maintainer machine, all projects.

- **Effort precedence, observed.** On Claude Code 2.1.306, `house-rules:builder` launched with an Agent-call `effort: "high"` sent `output_config.effort: "high"` on all 3 of its requests. A control launch with no `effort` sent `medium`, the builder's frontmatter pin, on all 3. Both ran on `claude-sonnet-5-5`. So a call-level `effort` overrode the builder's frontmatter `effort`; other roster agents were not probed. Method: the `output_config.effort` field of each request in the subagent transcript.
- **Refuter verdicts are parseable.** A refuter's final report is delivered as the `input.message` of a `SubagentHandback` tool call in its subagent transcript, not as a text block. Anchoring on `## VERDICT` followed by ACCEPT or REWORK in that message parses 241 of 281 refuter transcripts; reading only text blocks parses 9. The earlier "1 of about 101" count came from reading the wrong part of the transcript, not from a missing verdict line, so M1 does not need a new verdict format. `scripts/verdicts.py` now reads the handback message.
- **Rework rate by builder model**, pairing each refuter with the most recent earlier builder launch in the same session and counting the first verdict per builder:

  | Builder | Builders launched | Refuted | First verdict REWORK | Rate |
  |---|---|---|---|---|
  | Opus 5.5 | 63 | 33 | 15 | 45% |
  | Sonnet 5.5 | 208 | 54 | 36 | 67% |
  | Sonnet 5 | 53 | 0 | 0 | n/a |

  165 verdicts paired; 76 refuter verdicts had no earlier builder in the session. `scripts/verdicts.py` reproduces this within a few runs (Opus 5.5: 37 refuted, 18 REWORK, 49%; Sonnet 5.5: 56 refuted, 38 REWORK, 68%); it also pairs 6 Sonnet 5 verdicts the session's count did not, and leaves 81 unpaired, from dedup and pairing details.
- **Cost per build, last 7 days:** Opus builder $86.16 over 24 agents (about $3.59 each); Sonnet builder $53.60 over 80 agents (about $0.67 each).
- **Arithmetic.** The gap is 22 points, under the 30 to 40 point break-even, so Sonnet-first stands on this data. If every Sonnet REWORK led to a full Opus rebuild, Sonnet-first costs about 0.67 + 0.67 x 3.59 = $3.08 per build against $3.59 for Opus-first.
- **Caveats.** The pairing is a heuristic. Opus got the harder builds, so the comparison is not controlled; that bias works against Sonnet-first, since on matched tasks the gap is likely wider and closer to the break-even. A REWORK is caught by the refuter, so the quality floor is the review, not the builder.

- How much of a typical session's spend is a conventions plugin's always-on footprint, against tool output and fan-out. Measurable with `claude plugin details`, `/context` and `query_source`.
